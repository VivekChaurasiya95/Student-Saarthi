# Student Saarthi - Comprehensive Project Audit

**Document Date:** November 2026  
**Auditor:** Senior Full-Stack Software Architect  
**Project:** Student Saarthi (Scholarship Discovery & Management Portal)  
**Status:** Audit Complete  

---

## 1. Executive Summary

**Student Saarthi** is an all-in-one scholarship discovery and application portal designed for Indian students to discover, track, and apply for government and private scholarships. 

The existing application was developed as a monolithic prototype consisting of:
- A single Python backend file (`app.py`, 989 lines) using Flask and `mysql.connector`.
- Standalone HTML files in the project root referencing local scripts and stylesheet (`styles.css`).
- Client-side vanilla JavaScript files making asynchronous `fetch` calls to hardcoded `http://127.0.0.1:5000/api` endpoints.
- Two Python virtual environments: `.venv` (incomplete, missing pip/packages) and `venv` (fully populated with Flask, mysql-connector, etc.).
- A cluttered directory layout with empty folders (`Html/`, `JavaScript/`) and text-based backup files inside `Css/`.

This audit establishes the baseline of existing functionality, backend/database architecture, vulnerabilities, and file relocation plans for modernizing the project into a modular, production-ready Flask application.

## 4. Database Architecture & Existing Schema

The prototype backend relied on direct raw SQL via `mysql.connector` connected to a local MySQL instance (`database: student_saarthi`, user `root`, password hardcoded in `DB_CONFIG`).

### 4.1 Existing Tables
1. **`users`**
   - Columns: `id` (VARCHAR 36, UUID PK), `full_name`, `email` (UNIQUE), `password` (SHA256 hex string), `phone`, `dob`, `gender`, `address`, `education_level`, `academic_percentage`, `field_of_study`, `institution_name`, `graduation_year`, `category`, `annual_income`, `special_circumstances`, `profile_completion` (INT DEFAULT 85), `created_at`, `updated_at`.
2. **`admins`**
   - Columns: `id` (VARCHAR 36 PK), `username` (UNIQUE), `password` (SHA256 hex string), `email`, `created_at`. Default admin: `admin` / `admin123`.
3. **`scholarships`**
   - Columns: `id` (INT AUTO_INCREMENT PK), `name`, `provider`, `amount` (DECIMAL), `category`, `description`, `min_percentage` (FLOAT), `education_levels` (TEXT comma-separated), `eligible_categories` (TEXT comma-separated), `max_income` (INT), `age_limit` (INT), `deadline` (DATE), `required_documents` (TEXT comma-separated), `status` (VARCHAR, 'active'), `max_applicants` (INT), `current_applicants` (INT DEFAULT 0), `created_at`.
4. **`applications`**
   - Columns: `id` (VARCHAR 36 PK), `user_id` (FK -> users.id CASCADE), `scholarship_id` (FK -> scholarships.id CASCADE), `application_status` ('Submitted', 'Under Review', 'Approved', 'Rejected'), `statement_of_purpose` (TEXT), `additional_info` (TEXT), `applied_date`, `last_updated`, `admin_notes` (TEXT).
5. **`bookmarks`**
   - Columns: `id` (INT AUTO_INCREMENT PK), `user_id` (FK -> users.id CASCADE), `scholarship_id` (FK -> scholarships.id CASCADE), `created_at`, UNIQUE KEY (`user_id`, `scholarship_id`).

### 4.2 Deficiencies in Existing Database Design
- **Tight Coupling to Local MySQL Server:** Fails to boot if local MySQL server is not running or if port 3306 is inaccessible. No abstraction for SQLite for development/testing or standard connection strings via `DATABASE_URL`.
- **No Document Storage Relation:** The application asks users to have documents ready, but there is no `application_documents` table to record uploaded files, document types, or file paths.
- **No Notifications Table:** No schema exists for alerts, deadline reminders, or status updates sent to students.
- **No Saved Contact Messages:** The contact page submits nothing to the backend.
- **Unsalted SHA256:** Passwords stored as unsalted `hashlib.sha256(password.encode()).hexdigest()`.

## 5. Security & Architectural Audit

### 5.1 Critical Security Vulnerabilities Identified
1. **Arbitrary Local File Exposure via Wildcard Route:**  
   `app.py` line 129: `@app.route('/<path:path>')` uses `send_from_directory('.', path)`. Any client could download `app.py`, log files, database configuration, or internal scripts.
2. **Weak Password Hashing:**  
   Passwords use single-round unsalted SHA-256. Must be replaced with Werkzeug's PBKDF2/scrypt (`generate_password_hash` / `check_password_hash`).
3. **Hardcoded Database Credentials:**  
   Root password `Mithla@062061` was committed directly inside `app.py`. Must be moved to `.env` configuration.
4. **Ephemeral Secret Key:**  
   `app.secret_key = os.urandom(24)` generated a new secret on every server restart, invalidating all user sessions instantly. Must use persistent `.env` key.
5. **Lack of File Upload Sanitization:**  
   Missing secure filename handling, file size restrictions, and MIME-type validation.
6. **Hardcoded Host URLs in Frontend Scripts:**  
   Frontend JS files hardcode `http://127.0.0.1:5000/api`. If served via a different port or domain, API requests break or trigger CORS restrictions.

## 6. Virtual Environment Audit

- `.venv/`: Contains only `Scripts/python.exe`, `Scripts/pythonw.exe`, and `pyvenv.cfg`. Running `python -m pip` returns `No module named pip`.
- `venv/`: Complete environment containing Python 3.13.7 with all required runtime dependencies (Flask 3.0.0, Flask-Cors 4.0.0, mysql-connector-python 8.2.0, Werkzeug 3.0.1, python-dotenv 1.0.0, requests 2.32.5, google-auth 2.43.0, Jinja2 3.1.6).
- **Consolidation Plan:** Recreate `.venv` with complete pip and dependencies + SQLAlchemy, verify functionality, exclude both from Git, and remove redundant `venv/`.

## 8. Summary of Planned Enhancements

1. **Architecture:** Flask Application Factory pattern (`create_app()`) with Blueprints for `main`, `auth`, `student`, `scholarships`, `applications`, `admin`, and `contact`.
2. **Database:** Robust SQLAlchemy ORM supporting both SQLite (`instance/database/student_saarthi.db`) and MySQL/Postgres seamlessly via `DATABASE_URL`.
3. **Seed Data:** Extract the 10 authentic government and corporate scholarships from the legacy files and seed them into the database on startup.
4. **Security:** Implement industry-standard password hashing (Werkzeug scrypt/pbkdf2) with legacy SHA256 migration support, secure session management, input validation, and file upload validation.
5. **Testing:** Automated test suite covering health, auth, scholarships, applications, admin access control, and route resolution.
